# SnipasteOCR

仿 Snipaste 的截图 OCR 小工具:按热键框选屏幕区域,本地离线识别文字,支持部分选词、复制、保存。

基于 .NET 10 WinForms + NativeAOT,发布后是**单个原生 exe**,无需安装 .NET 运行时;OCR 引擎 [SimdPaddleOCR](https://github.com/Sdcb/SimdPaddleOCR) 与中文识别模型全部内嵌,识别过程**完全离线**。翻译是**可选的联网功能**,默认关闭,只有主动点「翻译」才会把识别出的文字发送到 DeepSeek。

## 功能

- **F1** — 截屏 OCR:框选区域后松开鼠标立即识别,弹出结果窗口
- **F3** — 截屏标注:框选后选区下方浮出标注工具栏,可绘制**矩形 / 椭圆 / 箭头 / 画笔 / 马赛克 / 文字**,确认后以 PNG 复制到剪贴板
- 框选时自带**放大镜 + 取色器**:光标旁显示 15×15 物理像素放大网格、屏幕坐标与 HEX/RGB,按 `C` 复制当前像素颜色
- **识别剪贴板图片**(托盘菜单):不用先贴到屏幕上,直接识别已复制的图
- **延时截图**(托盘菜单):3/5 秒后自动打开截图界面,方便截菜单、下拉框、悬停提示
- **热键可自定义**(托盘菜单 → 热键设置),用于避开被 PixPin / IDE 等占用的 F1/F3;
  两个热键可分别录制各自的组合键,托盘菜单会同步显示实际生效的按键
- **可在托盘菜单切换识别模型**(高精度 / 快速),选择会被记住
- **开机自动启动**(托盘菜单勾选,写 HKCU 的 Run 键,无需管理员权限)
- **防止电脑休眠**(托盘菜单勾选,运行期间阻止空闲休眠与息屏,详见下)
- **结果支持阅读顺序排序与多种导出**(表格 / CSV / 段落 / Markdown),方便从截图里的表格取数
- **单击识别结果即复制**:结果窗口里点一下文本块就复制该块;托盘菜单可关闭该行为
  (与「单击翻译」互斥:开启翻译会自动关闭复制,托盘勾选始终反映真实行为)
- **可选 AI 翻译**(结果窗口 →「翻译」):有选中译选中、未选中译全部,译文在独立窗口对照显示;
  可另开「单击文字块直接翻译」,译文直接贴在结果窗口底部,条上自带「复制」,边看边译(默认关闭);
  **默认自动判断中↔英方向**(中文译英文、英文译中文),也可固定目标语言;
  首次使用会明确提示联网,**识别本身仍全程离线**;API Key 只保存在本机(DPAPI 加密),详见下
- 支持鼠标右键托盘菜单触发,热键被占用时会提示
- 识别结果窗口:
  - 按截图原始尺寸 1:1 显示,缩放时窗口跟随图片大小联动
  - 单击文本块即选中整块并**自动复制**(托盘菜单 →「单击复制识别结果」可关闭)
  - 在翻译设置里开启「单击文字块翻译」后,单击改为**直接翻译该块**,译文贴在窗口底部;
    译文条右上角可**一键复制译文**,`×` 或单击空白处收起
    (单击翻译后不再自动复制原文,`Ctrl+C` 仍可复制原文)
  - 在文本块内**按住拖动可部分选词**(像选网页文字一样)
  - 低置信度文本块用橙色虚线框标出(只提示不过滤),鼠标悬停时状态栏显示「置信度 xx%」
  - 双击选中英文单词/连续汉字/数字,三击选中整行(选词动作本身不触发自动复制)
  - `Ctrl+C` 复制选中内容(整行或选中的字符范围),`Ctrl+A` 全选
  - `Ctrl+滚轮` / `+` / `-` 缩放(以鼠标位置为锚点),`0` 适应窗口;放大后中键拖动、空格+左键或滚轮平移,`Esc` 关闭
  - 一键复制全部 / **复制表格** / **复制 CSV** / **复制段落** / **复制 MD** / 保存截图为 PNG

### 四种导出方式的区别

| 按钮 | 输出 | 适用场景 |
| --- | --- | --- |
| 复制全部 | 每行原文,按阅读顺序 | 保持原样 |
| 复制表格 | 按坐标重建为制表符分隔,可直接粘进 Excel | 截图里是表格 |
| 复制 CSV | 同上,逗号分隔 | 导入数据库/脚本 |
| 复制段落 | 合并为连贯段落,**去掉排版造成的硬换行** | 粘进文档、聊天 |
| 复制 MD | 段落之间空行分隔 | 粘进 Markdown 文档/Issue |

> 「复制段落」与「复制 MD」共用同一套断句逻辑,因此同一屏文字用两种格式导出,
> 断行位置必然一致(不会一个地方合并、另一个地方断开)。


## 截图识别(F1)

框选区域后**松开鼠标立即开始识别**,覆盖层直接关闭并弹出结果窗口,不需要再点「确认」。
识别模式不显示标注工具栏(矩形/马赛克/文字等只属于 F3 标注流程);需要标注请按 F3。

## 放大镜与取色器

按 F1/F3 打开覆盖层后,光标旁会出现放大镜:

- 显示光标周围 **15×15 个物理像素**的放大网格,中心像素用蓝框标出;
- 下方显示当前像素的 **HEX**、**RGB** 与屏幕坐标;
- 按 `C` 把当前像素颜色以 `#RRGGBB` 复制到剪贴板,底部提示「已复制 #RRGGBB RGB(...)」;
- 贴近屏幕右/下边缘时自动翻到另一侧,不会盖住光标,也不会被屏幕裁掉;
- 框选完成后自动隐藏,给工具栏和选区内容让位;取色器仍可用(光标停在工具栏上时除外)。

> 取色读取的是覆盖层启动时抓取的整屏底图,不是重新抓屏,因此不会把遮罩/放大镜本身取进去;
> 放大镜只是覆盖层上的辅助控件,不参与最终导出,保存/识别的图片里不会出现它。

## 截图标注(F3)

框选完成后,选区下方会自动浮出工具栏(贴近屏幕边缘时自动翻转到选区上方)。

| 工具 | 快捷键 | 操作 |
| --- | --- | --- |
| 矩形 | `1` | 按住拖拽出矩形框 |
| 椭圆 | `2` | 按住拖拽出椭圆框 |
| 箭头 | `3` | 从起点拖向目标,箭头指向终点 |
| 画笔 | `4` | 按住自由绘制(轨迹自动去抖) |
| 马赛克 | `5` | 按住拖出打码区域,块平均像素化,适合遮挡密码/隐私 |
| 文字 | `6` | 点击定位后就地输入,回车确认、`Esc` 取消 |

**样式**:点色块循环切换 8 种颜色,点线宽按钮切换 3 档粗细。

**尺寸提示**:拖拽框选时,选区上方会实时跟随显示 **宽 × 高**(单位:物理像素,即最终导出/识别的真实尺寸);
贴到屏幕边缘时标签自动移到选区内侧或水平回退,不会被屏幕裁掉;选区贴底、工具栏翻到上方时标签会让到工具栏之上。
松手后仍保留显示。

**快捷键**:`Ctrl+Z` 撤销、`Ctrl+Y` 重做、`Delete` 清空全部标注、`0` 退回纯框选、`回车`/双击确认、`Esc` 退出当前工具、`右键` 先清空标注再退出。
**直接识别**:`Ctrl+回车`(或按住 `Ctrl` 点「确认」)跳过剪贴板,把标注后的图直接送 OCR。
之所以复用一个确认入口而不是再加按钮:工具栏宽度已到紧凑上限,再加文字按钮会撑大小选区上的浮层。

**确认动作**:与原来一致 —— F3 模式下标注会**烧录进图片**一起复制到剪贴板(不做成独立图层);
工具栏上的「保存」按钮可另存为 PNG 到 `图片\SnipasteOCR\`。
若剪贴板被其它程序占用导致复制失败,覆盖层会**保持打开**并提示,不会把截图丢掉;保存失败同样保留现场。

**贴图(钉住)**:工具栏上的图钉按钮把选区连同标注**钉成桌面上的置顶小窗**,
原样浮在其它窗口之上,适合"对照着截图在别处操作"的场景(不会写入剪贴板,也不弹识别窗口)。

- **左键拖动**移动位置,**右键关闭**贴图;可同时钉多张,各自独立。
- 贴图**不抢焦点**:钉住后你正在输入的程序不会被打断。
- 显示为 **1:1 原始像素**(100% 缩放),不做拉伸,所见即截图本身。
- 与「确认」的区别:「确认」是把图**交出去**(复制到剪贴板 / 送去做 OCR),
  「钉住」是把图**留在屏幕上**继续看。

> 标注只在选区内可见与生效,与最终导出一致 —— 预览看到什么,导出的就是什么。
> 马赛克直接从原图取样,不会把下方的其它标注也糊进去。

## 延时截图

右键托盘图标 → **延时截图** → 3/5 秒后截图识别或截图标注。

点完托盘菜单后系统菜单会立刻收起,想截的下拉框/右键菜单来不及出现;延时给你留出打开它的时间。
开始倒计时时会弹一条托盘气泡提示,不会让你以为点了没反应。延时只作用于这个菜单入口,平时按 F1/F3 仍是立即截图。

## 配置

设置保存在 `%LOCALAPPDATA%\SnipasteOCR\settings.json`,全部可在托盘菜单里改:

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| `modelProfile` | 识别模型档位 (0=高精度, 1=快速) | 0 |
| `hotKeyOcr` / `hotKeyImage` | 两个热键的虚拟键码 | F1 (0x70) / F3 (0x72) |
| `hotKeyModifiers` / `hotKeyImageModifiers` | 两个热键**各自**的修饰符 (Ctrl=2, Alt=1, Shift=4, Win=8, 可相加);旧配置缺第二项时自动继承第一项 | 0 / 0 |
| `sortReadingOrder` | 结果是否按阅读顺序重排 | true |
| `runAtStartup` | 是否开机自启 (与注册表实际状态保持一致) | false |
| `preventSleep` | 是否防止电脑休眠/息屏 (与真实生效状态保持一致) | false |
| `translateApiKeyProtected` | DeepSeek API Key 的 DPAPI 密文 (Base64);界面里只显示末 4 位 | 空 |
| `translateModel` | 翻译模型名 | `deepseek-flash` |
| `translateTargetLanguage` | 翻译目标语言;`自动（中↔英）` 表示中文译英文、英文译中文 | `自动（中↔英）` |
| `translateConsentGiven` | 是否已同意把识别文字发送到 DeepSeek | false |

> 配置读写失败 (文件损坏/无权限) 时自动回退默认值,不影响启动。
> NativeAOT 下 JSON 使用**源生成**序列化 (`SettingsJsonContext`),否则会被裁剪器移除。

> **开机自启实现方式**:写当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
> (无需管理员权限,不会触发 UAC)。托盘菜单的勾选**以注册表实际状态为准** ——
> 若你在任务管理器里手工禁用了它,下次打开菜单会显示为未勾选,不会骗人。
> 注册表被策略锁定时菜单项会提示失败,但**不会影响程序其它功能**。

### 防止电脑休眠

右键托盘图标 → **防止电脑休眠**,勾选后程序运行期间会阻止系统因空闲而休眠或关闭显示器,
适合长时间跑识别、看文档、等任务时使用;取消勾选立即恢复系统原有电源行为。选择会被记住。

用的是 Windows 官方接口 `SetThreadExecutionState`(声明"本线程正在使用中"),
**不会移动鼠标、不产生任何键盘/鼠标事件**,因此不会干扰你正在进行的操作。

> **为什么不做成"定时微移鼠标"**:模拟鼠标移动虽然也能骗过空闲检测,但副作用很实在 ——
> 会抢走用户正在操作的鼠标(拖拽中断)、屏幕录制时光标乱抖,而且**本程序自己的全屏截图/标注
> 覆盖层**(F1/F3)会被它破坏:框选过程中光标被程序偷偷移走,选区的起点就对不上了。
> 官方接口零副作用,是同样目的下唯一正确的做法。
>
> 另外它**不需要定时器**:配合 `ES_CONTINUOUS` 只需调用一次就持续有效,
> 也就不存在"定时器漂移或中途失效"的问题。

> **它拦不住什么**(如实说明,避免误解):只阻止**空闲触发**的休眠与息屏。
> **合上笔记本盖子、按电源键、开始菜单里的"睡眠/休眠"、屏保或组策略触发的锁屏**
> 都不受此设置影响 —— 那些属于用户主动或策略强制行为,应用层无权阻止。
> 若需要连合盖也阻止,请在 Windows「电源选项」里把"合上盖子时"设为"不采取任何操作"。
>
> 若系统不支持该接口或被安全策略拦截,勾选时会弹窗提示,且勾选会**自动回到未勾选** ——
> 不会出现"显示开着但其实没生效"的假象。

### 翻译(可选联网)

右键托盘图标 → **翻译设置…** 填写 DeepSeek API Key(在 DeepSeek 平台申请)后,
在识别结果窗口点「翻译」:

- 有选中文本时只翻译选区,未选中时翻译全部(与「复制」的范围语义一致);
- **默认自动判断方向**: 中文原文译成英文、英文原文译成中文;也可在翻译设置里固定目标语言;
- 译文默认在独立窗口显示(居中于结果窗口所在屏幕),可复制,`Esc` 关闭;
- 可选「单击文字块翻译」:开启后单击识别文本块即翻译该块,译文贴在**结果窗口底部**,
  不打开独立窗口;译文条自带「复制」按钮,连点别的块会取消上一次请求,译文条不会被旧结果覆盖;
- 首次点击会明确告知并询问是否允许把**文字**发送到 `api.deepseek.com` ——
  **不上传截图**,拒绝则不发送;同意状态可在翻译设置里撤销;
- 单次最多翻译 8000 字,超出部分截断并在窗口标题标注;
- 自动关闭思考模式(`thinking: disabled`),控制延迟与费用。

> **隐私与离线边界**: OCR 与标注仍然**完全离线**;只有你主动点「翻译」时才会发出一次
> HTTPS 请求,请求体只有识别出的文字。API Key 用 Windows DPAPI(CurrentUser)加密后写入
> `settings.json`,换机器/换账户后需要重新输入;程序不记录请求/响应日志。
> 费用由 DeepSeek 按 token 计费(以其官方价格为准),一屏文字通常在分币级。

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 1809+ / Windows 11 (x64) |
| CPU | 需支持 AVX2(2011 年后的 Intel/AMD 桌面/移动 CPU 基本都支持) |

> AVX2 是 SimdPaddleOCR 在 NativeAOT 下启用 SIMD 内核的硬性要求,否则推理速度会差一个数量级,因此发布时固定编译为 AVX2 指令集。

## 快速开始(发布产物)

发布后的 `SnipasteOcr.exe` 单文件即可运行(约 163 MB,内含高精度 + 快速两套模型):

```
SnipasteOcr.exe      # 启动后驻留系统托盘
```

启动后按 **F1** 框选区域,稍等识别完成即可在结果窗口中选择、复制文字。

## 识别模型切换

内置两套中文模型,**右键托盘图标 → 识别模型** 即可切换,切换立即生效(下一次识别时加载):

| 档位 | 模型 | 模型体积 | 速度 | 适用场景 |
| --- | --- | --- | --- | --- |
| 高精度(默认) | PP-OCRv6 Medium | 132 MB | 基准 | 小字、模糊、形近字、表格与代码 |
| 快速 | PP-OCRv6 Tiny | 6 MB | 约快 9 倍 | 正常字号的印刷体、段落、英文数字 |

实测字符准确率(困难样本,越小越难):

| 场景 | Medium | Tiny |
| --- | --- | --- |
| 极小字 / 表格 | 100% | 83% |
| 密集代码 | 100% | 92% |
| 缩放后略模糊 | 100% | 89% |
| 形近字(未末土士己已巳) | 93% | 86% |
| 正常字号印刷体 / 段落 / 英文 | 100% | 100% |
| **平均** | **99.0%** | **95.8%** |

> 结论:屏幕截图通常很清晰,Tiny 在正常字号下完全够用;但**小字和模糊场景** Medium 明显更准。
> 因为两者都打包进 exe,体积为两者之和(约 163 MB),换来的是随时切换、无需重新发布。

切换只需登记请求,真正的模型加载发生在其后的第一次识别(后台线程),不会卡住界面。


## 从源码构建

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)。

此外, NativeAOT 发布还需要 **Visual Studio Build Tools 的「使用 C++ 的桌面开发」工作负载**
(MSVC x64/x86 生成工具 + Windows 10/11 SDK)。只装 .NET SDK 会在链接阶段报
`Platform linker not found`。安装方式: 打开 Visual Studio Installer → 修改已安装实例
(或安装 Build Tools, 不必装完整 IDE) → 工作负载 → 勾选「使用 C++ 的桌面开发」→ 安装。
验证: `<VS>\VC\Auxiliary\Build\vcvarsall.bat` 存在, 且
`vswhere -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64` 能返回安装路径。
仅有 `link.exe` 不代表环境可用 —— 缺 `vcvarsall.bat`/库/SDK 时仍会链接失败。

以下命令均在**仓库根目录**执行(产品代码在 `src/`,不在仓库根):

```powershell
# 推荐: 一键发布脚本 (自动清理残留/占用, 可选自检与打包)
# 直接双击 scripts\publish.cmd 等效于下面第一条(发布 + 打包到 dist\)
.\scripts\publish.ps1                              # 发布 + 打包出 zip 到 dist\
.\scripts\publish.ps1 -SelfTest                    # 发布 + 离线自检 + 打包
.\scripts\publish.ps1 -OutputDir '' -SelfTest      # 只要发布产物, 不打包

# 手工发布
dotnet build src/SnipasteOcr.csproj -c Debug
dotnet publish src/SnipasteOcr.csproj -c Release -r win-x64 --self-contained -p:PublishAot=true
```

> **想双击就跑,请双击 `scripts\publish.cmd`,不要双击 `publish.ps1`。**
> Windows 下双击 `.ps1` 默认是用记事本打开、**根本不会执行**;即使已关联到 PowerShell,
> 窗口也会在结束时立刻关闭,报错一闪而过 —— 表现就是"双击了但没打包成功"。
> `publish.cmd` 会调用脚本并在结束时停留显示结果与退出码。

### 发布脚本

`scripts/publish.ps1` 把上面的手工步骤固化成一步,并处理实测踩过的坑(残留文件导致的 `LNK1104`、
旧实例占用产物、单实例互斥等):

| 参数 | 作用 |
| --- | --- |
| *(无参数)* | 发布 + 打包到 `dist\`(`-OutputDir` 默认即 `dist`) |
| `-SelfTest` | 发布后跑离线自检(215 项,无需桌面会话)。**正式出包建议带上** |
| `-OutputDir <目录>` | 打包输出目录,默认 `dist`;传 `''` 则只发布不打包 |
| `-IncludePdb` | 打包时附带 46MB 调试符号(默认不带,分发不需要) |
| `-NoZip` | 只输出目录,不压缩 |
| `-SkipClean` | 跳过清理。省几十秒,但 `LNK1104` 会原样复现 |
| `-Configuration <配置>` | 构建配置,默认 `Release` |

> 脚本不受调用目录限制(以自身位置推导仓库根),但需 **PowerShell 5.1+**。
> 它**不会**覆盖 `IlcInstructionSet=avx2`,也**不会**使用 `-p:PublishSingleFile=true` —— 这两点都会破坏产物品质。
>
> `.cmd` 与 `.ps1` 的编码/行尾有讲究(踩过坑,别改):`publish.ps1` 含中文,**必须带 UTF-8 BOM**
> (否则 `powershell.exe -File` 按 ANSI 读取,中文变乱码并触发语法错误);
> `publish.cmd` 由 `cmd.exe` 解析,**必须是不带 BOM 的 GBK + CRLF 行尾**
> (LF 行尾会让 cmd.exe 吞掉行首字符)。`.gitattributes` 已用 `*.cmd text eol=crlf` 固定行尾。

产物位于 `src/bin/Release/net10.0-windows/win-x64/publish/`,该目录下只有 `SnipasteOcr.exe`(约 163 MB)与 `SnipasteOcr.pdb`,
前者单文件即可分发,`.pdb` 是调试符号,**不必随包发布**。

> 发布踩坑:若报 `LNK1104: 无法打开文件 "…\native\SnipasteOcr.exe"`,通常是上一次构建在
> `src/bin/Release/net10.0-windows/win-x64/native/` 里留了残留文件(或 exe 仍在运行占用文件)。
> 先结束所有 `SnipasteOcr` 进程,再 `Remove-Item src/bin/Release -Recurse -Force` 后重试即可。
> 构建失败时请**不要**改用 `-p:PublishSingleFile=true`:单文件是由 AOT 产出的,模型靠**嵌入资源**加载,
> 换用其它单文件开关会破坏模型加载。

### 标注引擎自检

标注引擎的几何、命中测试、撤销栈、渲染与交互都有自动化验证。两个工程都**链接产品源码**而非复制,保证验证对象即实际出货代码:

```powershell
# 1) 离线自检 (434 项): 几何 / 命中 / 历史 / 像素级渲染 / 工具栏布局 / 尺寸徽标 / 设置迁移 / 文字编辑框 / OCR 后处理 / 选词几何 / CTC 字符框 / 翻译客户端 / 译文条布局
dotnet run --project tests/AnnotationTests                  # 无需桌面会话
dotnet run --project tests/AnnotationTests -- sample        # 额外输出一张六种标注的样例图, 便于目视确认

# 2) 交互自检 (151 项): 真实窗口/按键、拖拽实时尺寸、托盘文案、单击复制/单击翻译、底部译文条、窗口 DPI 基准、CTC 选词与翻译窗口居中、Ctrl+回车直接识别、延时截图、贴图 DPI
dotnet run --project tests/InteractiveTests                 # 需要可用的桌面会话 (会真正创建窗口并抓屏)

# 3) 端到端驱动 (可选): 用真实鼠标/键盘事件操作实际出货的 exe, 并抓屏取证
dotnet run --project tools/DriveTest -- <SnipasteOcr.exe 的完整路径>
```

> 以上统一用 `--project` 而不是 `cd <目录>; dotnet run` —— 直接在工程目录里 `dotnet run` 在
> `tests/`、`tools/` 下都会因目录内存在多个工程而无法确定要运行哪一个。

覆盖点包括反向拖拽的矩形归一化、椭圆包围盒死角的精确排除、箭头的头宽大于线体、马赛克的 block 级量化且不引入偏色、`clip`/`skip` 参数生效、退化标注不绘制、撤销栈快照与原对象隔离、**编辑框非零初始尺寸**、**编辑期间窗体的 `ProcessCmdKey` 让行**、**编辑框确实获得键盘焦点**,以及**输入文字确实被绘制到窗体上**(回归检查: 历史上因透明子控件被父窗口覆盖而完全不可见)。

> OCR 后处理一组断言的是**契约而非实现**: 「阅读顺序排序」与「表格重建」必须把同一批结果切成同样的行。
> 这两处原先各写了一份几乎相同的纵向聚类,容差公式一旦漂移,同一批识别结果会在结果列表里是一行、
> 到了「复制表格」里却变成两行 —— 因此该断言特意用同一输入分别走两条路径再比对行数。
> 校验方式为**变异测试**: 人为把行聚类容差改坏后,该组必须报出失败(实测 8 项失败,且不因越界而崩溃)。

> 验证经验: 反射直接调用控件方法会**绕过真实的焦点链与绘制路径**,从而掩盖 bug。
> 因此凡是涉及"焦点 / 输入 / 可见性"的行为,都要用真实窗口 + 真实按键来验证;
> 断言也应检查**画面像素**而非仅检查控件状态。

## 技术要点

- **NativeAOT + 裁剪**: `IsAotCompatible=true`、`IlcInstructionSet=avx2`;OCR 引擎与模型通过程序集嵌入资源加载,需在 `TrimmerRootAssembly` 中显式保留(**两套模型程序集都要保留**,否则运行时切换会找不到资源),`PublishAot` 默认开启。
- **AOT 安全的 JSON**: 配置用 `JsonSerializerContext` **源生成**序列化。直接用反射式 `JsonSerializer` 会在裁剪后运行时失败 —— 这是 NativeAOT 最常见的坑之一。翻译请求/响应同样走 `TranslateJsonContext`,不例外。
- **翻译不改变离线主路径**: OCR 与标注代码不引用任何网络模块;只有结果窗口点「翻译」时才由独立 `TranslateClient` 发一次 HTTPS 请求。首次点击需知情同意,只发送 OCR 文字、不发送截图。
- **翻译必须显式关闭思考模式**: DeepSeek 默认开启 thinking,`reasoning_content` 按输出 token 计费并显著拉长等待;请求体固定带 `{"thinking":{"type":"disabled"}}`,并对 429/503 只退避重试一次。
- **API Key 不明文落盘**: 设置文件在 `%LOCALAPPDATA%` 下、同机进程可读;Key 经 Windows DPAPI(CurrentUser)加密后以 Base64 写入 `translateApiKeyProtected`。换机器/账户解密失败时提示重新输入,绝不回退明文。
- **模型档位切换**: `OcrService` 用 `_requestedProfile`(int,`Volatile` 读写)记录请求、`_loadedProfile` 记录实际已加载档位,两者不一致时在下一次识别中释放旧引擎并加载新模型。**取引擎与推理在同一个锁内完成**,避免切换时 `Dispose()` 打断另一线程正在进行的 `Run()`。
- **热键可换不丢**: `HotKeyManager` 换键时**先注册新键,成功后才注销旧键**,失败则回滚保留原热键,避免"换失败导致两个热键都没了"。
- **表格重建**: 结果块的包围盒先按纵向重叠聚类成行; 列不再按左边界聚类, 而是取「单元格数最多的行」做参考, 把单元格的 `[Left, Right]` 投影到 x 轴, 按区间空隙两侧的单元格数量与宽度选列分隔, 再按最大重叠把单元格归入列带。居中表头与右对齐数字不会再被拆成多列; 跨列表头通常只占一格, 不会被当作参考行桥接列间空白。缺失单元格留空以保持列对齐。**分词行这一步 (`OcrText.ClusterRows`) 与「阅读顺序排序」共用同一实现** —— 两处各写一份的话, 容差一旦漂移就会出现"列表里一行、表格里两行"的不一致。
- **Per-Monitor DPI v2**: 截图是物理像素, 窗口客户区是逻辑像素, 绘制/命中/字符定位三套坐标统一经 DPI 换算。结果窗口缓存**窗口自身**的 DPI(`OnHandleCreated` / `OnDpiChanged`), 不再用 `Graphics.FromHwnd(IntPtr.Zero)` 取主屏 DPI —— 否则窗口移到不同 DPI 的副屏后, 图片尺寸、命中与字符高亮会整体偏移。
- **字符级选词 (CTC)**: `OcrService` 以 `returnCtcAlignment: true` 调用引擎, 每行带 `CtcSpans`; `OcrGlyphLayout` 调 `EstimateCharacterBoxes()` 得到逐 token 四边形, 展开到 UTF-16 字符并归一化成文本轴光标边界。命中按真实字符边界判定, 高亮直接填充逐字四边形; 180° 旋转由引擎还原, 空格是独立 span。CTC 缺失、字符数不一致或竖排行时回退到宽度权重(汉字 1.0 / ASCII 0.6 / 空格 0.35), 保证选词不失效。按**字符中线**判定光标位置, 拖到行尾能得到 `n`、完整包含最后一个字符。实测 Tiny 档开启 CTC 的 p50 差异在测量噪声内(约 1%)。
- **多选复制顺序**: 多选与 `Ctrl+A` 的结果按阅读顺序名次拼接,与「复制全部」「复制段落」一致;名次由 `OcrSelection.BuildReadingRanks` 复用 `OcrText.SortReadingOrder` 生成,不另写一套排序。
- **单击复制**: 只在"未拖动的左键单击检测块"时写剪贴板,复制范围就是当前检测块(与高亮框一致);拖选、`Shift` 多选、单击空白都不复制。开关默认开启,可在托盘菜单关闭,结果窗口每次单击都读取当前设置。
- **推理不锁图**: 识别前对位图做瞬时 `LockBits` 拷贝,推理在独立字节缓冲上进行,UI 线程可随时重绘。
- **标注坐标系统一**: 标注几何 **一律存物理像素**,与底图 `_screen` 同坐标系。覆盖层预览用 `Graphics.ScaleTransform` 缩放绘制,导出时用 `TranslateTransform` 平移 —— 同一份数据、同一个渲染引擎 (`AnnotationEngine`),因此**预览与导出像素级一致**,不会因 DPI 缩放错位。
- **文字描边色单一来源**: 文字标注的描边色(按填充色亮度决定用黑边还是白边)统一由 `AnnotationEngine.OutlineColorFor` 决定,正在输入的编辑框也调用它 —— 若编辑框自己再算一份,阈值一旦改动就会出现**编辑时看到的样子 ≠ 确认后烧录进图片的样子**,正好破坏上面那条"预览与导出一致"的承诺。
- **箭头几何单一来源**: 标注箭头与工具栏上的箭头图标都由 `AnnotationEngine.ArrowGeometry.TryCreate` 推导 (单位向量 → 法线 → 三角头)。该方法在起止点重合 (`len < 1px`) 时**返回 null 而不是放行 NaN** —— 原先工具栏图标自己算且没有这层保护,只是恰好起止点写成了常量才没暴露。
- **检测框四角单一来源**: `OcrBox` 统一展开 `PaddleOcrDetectionBox` 的扁平 `X1..Y4` 四角 (画框 / 命中测试 / 字符范围高亮 / 包围盒 / 轴对齐五处共用)。其中 `TopEdge` 与 `BottomEdge` 的取点顺序必须"同向"(`X1→X2` 与 `X4→X3`),否则按同一参数 `u` 插值出的高亮四边形会自交。
- **马赛克实现**: 对目标区域 `LockBits` 取原始像素,按 10×10 分块求平均色写入小位图,再用 `NearestNeighbor` 放大绘制得到硬边像素块。**直接从原图取样**而非从"已绘制的画面"取样,因此马赛克不会把其下方的其它标注一起糊进去。
- **撤销/重做**: 采用「快照 + 列表」而非命令模式。标注数量是手工量级 (通常 < 50),每次操作深拷贝一份列表代价可忽略,换来实现简单且不会出现逆操作写错的问题;深度上限 100。
- **工具栏自绘**: 不用 `ToolStrip` —— 覆盖层无边框且工具栏需跟随选区移动、贴近屏幕边缘时自动翻转,自绘才能精确控制尺寸与外观;图标全部矢量绘制,不依赖图片资源,AOT 友好且任意 DPI 清晰。
- **文字标注的就地编辑**: 自绘 `TextEditorOverlay` 而非 `TextBox`,以做到无边框 + 带描边文字,与最终合成效果一致。注意覆盖层设了 `KeyPreview = true`,编辑期间必须同时在 `ProcessCmdKey`/`ProcessDialogKey` 让行,否则输入的数字会被当作工具快捷键吞掉。
- **覆盖层必须自己抢前台**: `Form.Show()` 只显示、**不激活**窗口。截图工具是托盘常驻程序,若不做处理,覆盖层虽然置顶可见、鼠标也能操作,但**键盘焦点仍留在原程序**,表现为"能框选、能点工具栏,但打字没反应"。因此在 `OnShown` 里用 `AttachThreadInput` 挂到当前前台线程再 `SetForegroundWindow`(后台进程直接调用会被系统的前台锁定拒绝)。
- **输入文字的显示不走子控件**: 覆盖层在 `OnPaint` 里整屏绘制底图,而 WinForms 的 `SupportsTransparentBackColor` 依赖"父窗口先画好背景、子控件再叠加"的协作 —— 该协作在这里不成立,**透明子控件会被父窗口的整屏绘制覆盖,屏幕上完全看不到输入内容**(实测全屏逐像素对比: 打字前后 0 像素差异)。因此文字显示由覆盖层自己的 `DrawEditingText` 完成,`TextEditorOverlay` 被放到屏幕外、仅承担接收键盘输入的角色(焦点与可见性无关)。
- **不用字体画图标**: 工具栏图标(撤销/重做)全部**矢量绘制**,不依赖任何字体。原因是踩过坑:原先用 `↶`/`↷`(U+21B6/U+21B7) 配 `Segoe UI Symbol`,而**该字体在目标机器上并不存在**(回退到 Microsoft Sans Serif),且这两个码位在本机全部 229 个字体族中**都没有字形** —— 渲染结果为 **0 像素**,按钮一片空白且没有任何报错。
- **防休眠用官方接口而非模拟鼠标**:`SleepPreventer` 走 `SetThreadExecutionState`
  (`ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED`),不产生输入事件、不移动光标。
  两个关键约束:一是该状态是**线程级**的,必须由常驻的主消息循环线程调用,否则线程一退出就悄悄失效;
  二是**关闭时只传 `ES_CONTINUOUS`**(传 0 在部分系统上会被忽略,变成"关不掉")。
  另外该 API 的返回值是**调用前的旧状态**而非新状态,只能拿 `!= 0` 判断成败。
- **不画不存在的饼**:防休眠只防空闲休眠/息屏,拦不住合盖、电源键与策略锁屏,因此菜单文案用
  "防止电脑休眠"而非"保持屏幕常亮";调用失败时勾选自动回退,不留"显示开着但没生效"的假象。
- **字体按可用性探测**: 统一经 `UiFont` 创建。直接 `new Font("Microsoft YaHei UI", ...)` 在字体缺失时会**静默回退**到 Microsoft Sans Serif(中文可能显示不出来且不报错),因此改为按候选列表(`Microsoft YaHei UI` → `Microsoft YaHei` → `SimSun` → `SimHei` → `Segoe UI` …)逐个探测并缓存第一个真实存在的字体。

## 已知限制

- 中文识别为主,英文等西文字符可用但非最优
- 字符级选区优先使用 CTC 真实字符框; 引擎未返回对齐、字符数不一致或竖排行时回退到宽度比例估算(1~2 像素偏差)
- 竖排文字仍不支持准确选词: 当前投影沿检测框顶边进行, 竖排行会回退到不准确的权重估算
- 仅支持 x64 Windows;发布产物与编译机架构绑定,换架构需重新 publish
- 翻译需要联网并自备 DeepSeek API Key,离线环境不可用;单次最多 8000 字,非流式(译文一次性返回)
- 翻译只发送 OCR 文字,不发送截图;但文字本身可能包含敏感信息,请自行判断是否使用该功能

## 关于「翻译」的结论

**不内置本地翻译模型**;翻译通过可选的 DeepSeek API 提供(默认关闭、手动触发)。
完整评审(5 条本地路径对比、接口核对、成本与风险)见 [docs/archive/translate-review.md](docs/archive/translate-review.md)。

早期评估的是"把翻译模型打包进 exe",结论是**当前技术栈下不可行**:

本项目的 `Sdcb.SimdPaddleOCR.OnnxSharp` 虽含通用 ONNX 加载 API(`Model.LoadOnnx` / `InferenceSession`),
但实测**无法执行通用的 Transformer 翻译模型**:

| 验证对象 | 结果 |
| --- | --- |
| 本项目自带 OCR 模型 (正对照) | 4/4 加载成功 —— 证明探针正确 |
| NLLB `int8_encoder_model.onnx` | 失败:`InvalidDataException: ONNX TensorProto has no name` |
| NLLB `int8_encoder_kv_model.onnx` | 失败:`NotSupportedException: Unsupported ONNX tensor data type 3` |

根因:该引擎的 `DType` 只声明 `F32/I32/I64/U8`(且把 I64 编为 3,与 ONNX 规范中 `3=INT8` 冲突),
即**不支持 INT8 量化张量**,而主流可离线分发的 NMT 模型多为 INT8 量化。
另扫描其算子表,**缺少 `LayerNormalization` 与 `Attention`**,标准 Transformer 无法运行。

其他内置候选同样不合适:

- `LMSupply.Translator`:包内不含模型,运行时从 HuggingFace 联网下载(违背离线)
- `LocalAI.Translation` (NLLB):模型约 **1.5 GB**,依赖 `Microsoft.ML.OnnxRuntime.DirectML` **原生 DLL**(破坏单文件);且模型为 CC BY-NC 4.0 **仅限非商业**

因此当前实现不往 exe 里塞翻译模型:单文件体积与离线识别承诺不变,翻译是显式的可选联网动作。
若确实需要完全本地,可行路径是自建 OpenAI 兼容服务(Ollama / LM Studio)后把请求指向本机 ——
这只需要增加 BaseUrl 配置,属于后续扩展点;当前版本固定 DeepSeek 官方端点。
