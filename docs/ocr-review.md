# SnipasteOCR OCR 结果审查与扩展建议

日期: 2026-11-07 · 基线: `5afb0e7`

**范围**: `OcrResultForm` / `OcrText` / `OcrBox` / `OcrService` 的识别结果展示、选词、复制与导出。

**不包含**: 标注文字的字体渲染（已有 `UiFont` / 字形轮廓约束）；字体族识别（当前技术栈没有该能力，也不建议引入）。

**方法**: 逐行阅读相关代码；用反射核对 `Sdcb.SimdPaddleOCR 2.0.0` 的输出字段与 `returnCtcAlignment` API；
本机为双屏 100% 缩放，涉及混合 DPI 与真实鼠标点击的项标注了「待实机确认」。

**结论**:

- 没有 P0。发现 **2 个 P1**：字符拖选永远漏掉最后一个字符；混合 DPI 下坐标基准取自主屏。
- **4 个 P2 状态/顺序问题**：清空选中后仍保留隐藏的部分选区、多选复制顺序与阅读顺序不一致、
  `StatusChanged` 订阅泄漏、表格分列只认左边界；另有精度与缩放体验类 P2，见下文。
- 最大收益的扩展是 **单击自动复制**（改动小、直接命中用户诉求）；
  最大收益的识别优化是 **启用引擎的 CTC 逐字符框**，替换当前的宽度权重估算。
- 本次只写文档，未改产品代码。

## 一、正确性缺陷

### O-1 拖选永远选不到最后一个字符 — P1

- **位置**: `OcrResultForm.cs:484-497`（`CharIndexAt`）；`:616-619`（贴边收尾）。
- **现象**: 在文本块内从行首拖到行尾，高亮和复制内容都少最后一个字符；
  在行尾按住往左拖，同样选不到最后一个字符。
- **原因**: 方法注释写「0..n，n = 文本长度」，实现却返回 `0..n-1`：

  ```csharp
  for (int k = 0; k < cum.Length - 1; k++)
      if (cum[k] <= target) idx = k;
  return idx;
  ```

  `target = u * 总宽度`，`u` 被夹到 1 时 `target` 等于总宽度，循环仍只会把 `idx` 推到 `n-1`。
  因此 `:618` 的 `cur == t.Length` 永远不成立，所谓「拖到块边缘自动贴到行尾」是死代码。
- **复现**: 三个字符、累计宽度 `[0, 0.6, 1.2, 1.8]`；拖到右边缘 `target=1.8`，循环返回 `2`（`n-1`），
  `_partial = (0, 2)`，复制得到前两个字符。
- **建议**: 按字符中线判定光标位置，右半格返回后一个索引：

  ```csharp
  for (int k = 0; k < cum.Length - 1; k++)
      if (target < (cum[k] + cum[k + 1]) * 0.5f) return k;
  return cum.Length - 1; // = n
  ```

  这样拖到最后一个字符右半边会得到 `n`，最后一个字符可被包含；同时保留或重写贴边分支作为兜底。
  更彻底的做法见 O-7（直接用引擎的真实字符框）。
- **验证**: 把字符投影抽成纯函数后，离线断言「锚点 0 + 终点行尾 → `[0, n)`」「锚点 n + 终点行首 → `[0, n)`」。
- **改动面**: S（约 10 行 + 测试）。

### O-2 混合 DPI 下 DPI 基准取自主屏 — P1（待实机确认）

- **位置**: `OcrResultForm.cs:231-235`：

  ```csharp
  using var g = Graphics.FromHwnd(IntPtr.Zero);
  return g.DpiX / 96f;
  ```

  `FromHwnd(IntPtr.Zero)` 拿的是桌面 DC，即**主屏** DPI；本应用是 Per-Monitor V2
  （`SnipasteOcr.csproj:11`），窗口在副屏时这个值不会跟着变。
- **影响**: 主副屏 DPI 不同时，图片显示尺寸、`ImageRect`、`HitTest`、字符高亮、窗口初始大小
  全部按错误比例换算。例：主屏 150%、副屏 100%，窗口在副屏时图片会被画小 1.5 倍，鼠标命中偏移。
- **附带**: 该方法在 `BoxToClientPoints`（每行每帧）、`HitTest`、`OnMouseMove` 中反复调用，
  每次都创建一个 `Graphics`，属于无意义分配。
- **建议**: 缓存窗口自身的 DPI：

  ```csharp
  private float _dpi = 1f; // 句柄创建后 = DeviceDpi / 96f
  private float DpiFactor() => _dpi;
  ```

  在 `OnHandleCreated` 与 `OnDpiChanged` 里更新 `_dpi`，并重新计算 `_minScale`；
  构造函数里若句柄尚未创建，先按 96 计算初始尺寸，句柄创建后再校正一次。
- **验证**: 本机双屏同为 100%，无法实测混合 DPI；需在 100% + 150% 的机器上确认图片 1:1、
  框选命中和高亮不偏移。可先给 `DpiFactor` 留一个可注入的内部测试钩子，离线断言坐标换算。
- **改动面**: S。

### O-3 清空选中未清 `_partial`，出现「看不见的选区」 — P2

- **位置**: `OcrResultForm.cs:536-542`（空白处单击只清 `_selected`）；`:550-555`（Shift 取消最后一行）；
  `:374-386`（部分选区只在 `selected` 分支里绘制）；`:789-790`（没有 `_selected` 时仍返回 `_partial`）。
- **复现**:
  1. 在 A 行内拖选一段 → `_partial` 有值，`_selected={A}`。
  2. 单击空白处 → `_selected` 清空，但 `_partial` 保留。
  3. 画面上已经没有高亮；按 `Ctrl+C` 却仍复制出刚才那段部分选中的文字。
- **原因**: 「清空选中」散落在多处，只有部分路径清 `_partial`；绘制与复制对「是否有选区」的判据不一致。
- **建议**: 增加唯一的 `ClearSelection()`（清 `_selected`、`_partial`、`_hover` 的选区部分），
  空白单击、Shift 取消最后一行、`Ctrl+A` 全部走它；不要在调用点各写一遍。
  若产品语义是「Shift 取消后仍保留部分选中」，则绘制也必须显示它，不能只让复制看得到。
- **验证**: 离线状态机测试或 `InteractiveTests` 中的真实点击序列，断言「画面上无高亮时
  `GetSelectedText()` 为空」。
- **改动面**: S。

### O-4 多选 / Ctrl+A 的复制顺序不是阅读顺序 — P2

- **位置**: `OcrResultForm.cs:792` `_selected.OrderBy(i => i)`；对照 `:771-775` 的 `CurrentLines()`。
- **现象**: `_selected` 存的是 `_lines` 的检测顺序索引；PaddleOCR 的检测顺序在多列/多栏时可能
  右栏在前、左栏在后。`Ctrl+A`（`:737-742`）把所有索引按检测顺序加入后，
  `Ctrl+C` 得到的顺序与「复制全部」「复制段落」的阅读顺序不同。
- **建议**: OCR 完成时建立 `_lines` 索引 → 阅读顺序排名的映射（排序结果来自 `CurrentLines()`），
  `GetSelectedText` 按排名排序而不是按索引排序；这样 Shift 多选与 Ctrl+A 都和导出格式一致。
  映射在 OCR 完成与 `_wordOrder` 变化时重建一次，不要每次复制都重排。
- **验证**: `OcrTextChecks` 增加「输入顺序右栏在前、阅读顺序左栏在前」的断言；
  交互测试断言 Ctrl+A + Ctrl+C 与「复制全部」逐字相同。
- **改动面**: S。

## 二、状态、导出与健壮性

### O-5 `StatusChanged` 订阅未退订，窗口关闭后泄漏 — P2

- **位置**: `OcrResultForm.cs:92-97` 用匿名 lambda 订阅单例 `OcrService.Instance.StatusChanged`；
  `:924-930` 只取消 CTS、释放位图，没有退订。
- **影响**: 每打开一次结果窗口，单例事件链就多一个捕获 `this` 的委托；关闭后窗体对象
  （以及它持有的字段）无法回收。虽然 `IsHandleCreated` 挡住了对已关闭窗口的 `BeginInvoke`，
  但泄漏会随使用次数线性增长。
- **建议**: 保存委托到字段（如 `_statusHandler`），在 `OnFormClosed` 里 `-=`；
  若同一窗体可能重复订阅，先 `-=` 再 `+=`。
- **附带**: `OcrService` 在 `_gate` 内触发 `StatusChanged`（`OcrService.cs:126`, `:132`, `:150`），
  订阅者抛异常会直接中断识别。UI 订阅者目前只做 `BeginInvoke`，风险低；
  更稳妥的是把状态事件移到锁外触发，或对每个订阅者包 `try/catch`。
- **改动面**: S。

### O-6 表格分列只按左边界，居中/右对齐列会被拆散 — P2

- **位置**: `OcrText.cs:98-129`：列锚点取每个文本块的 `Left`，容差为 `max(6, avgHeight*0.6)`。
- **现象**: 同一列里表头居中、数字右对齐时，各单元格的 `Left` 差别很大，
  会被判成多个不同的列 → CSV 列数膨胀、值错位。现有 `OcrTextChecks` 的分列用例只覆盖了
  左对齐文本，没有覆盖居中/右对齐。
- **建议**: 不要用单一左边界做锚点，改为「列带」：
  1. 仍用 `ClusterRows` 分行（保持表格行语义）；
  2. 把每行单元格的 `[Left, Right]` 投影到 x 轴，按区间重叠/稳定的纵向空白切出列带；
  3. 每个单元格按中心点或最大重叠归入列带，缺失格留空；
  4. 跨列的表头（如「金额」横跨两列）按设计决定放在第一列还是拆开，需要样本确认。
- **验证**: 增加「居中表头 + 右对齐数字」「左对齐回归」「宽表头跨列」三组离线用例；
  保留现有左对齐用例不回归。
- **改动面**: M。

### O-7 字符定位是宽度估算，引擎已有 CTC 真实字符框 — P2 / 最高优先级识别优化

- **现状**: `OcrResultForm` 用 `CharWeight`（汉字 1.0 / ASCII 0.6 / 空格 0.35）把字符投影到行轴，
  再按累计宽度反解索引（`:455-497`）。这是 README 已记录的 1~2px 偏差来源。
- **引擎能力**（已用反射确认，包版本 2.0.0）:
  - `PaddleOcrAll.Run(..., bool returnCtcAlignment, ...)` 有独立重载；
  - `PaddleOcrLine.EstimateCharacterBoxes()` 返回 `PaddleOcrCharacterBox[]`；
  - `PaddleOcrCharacterBox` 有 `Text`、`Score` 与 `X1..Y4` 四角坐标；
  - 当前 `OcrService.cs:83` 调的是不带 `returnCtcAlignment` 的重载，等于放弃这份数据。
  包 README 明确说明该数据「适合做按字覆盖、打码」，默认关闭是为了不付额外开销。
- **收益**: 字符命中与高亮直接用真实四边形，彻底消除宽度权重误差；还能拿到逐字置信度，
  为 O-8、双击选词、跨行选区打基础。
- **代价与风险**:
  - 需要实测开/关的耗时差（README 未给具体数字），用 `tools/DriveTest` 或固定样本各跑 20 次比较 p50/p95；
  - 要验证 `EstimateCharacterBoxes()` 是否包含空格、坐标是否已应用 180° 旋转、字符数是否与 `Text` 一致；
  - 不一致时必须回退到现有权重算法，不能让整行选词失效。
- **建议落地**:
  1. `OcrService` 增加明确的参数或常量，调用 `returnCtcAlignment: true`（是否默认开由实测决定）；
  2. 新增纯函数类 `OcrGlyphLayout`（或放进 `OcrText`），负责「字符框 → 行内索引 / 高亮四边形 / 回退权重」；
  3. `OcrResultForm` 在 OCR 完成后为每行缓存字符框，绘制和命中不再自己算权重；
  4. `AnnotationTests` 增加字符数不一致、180°、空格、CTC 框缺失四类用例；
  5. 改引擎选项后必须真跑一次 AOT publish 并运行产物（AGENTS 的验证门槛）。
- **改动面**: M。

### O-8 已拿到 `RecognitionScore` 但界面完全不用 — P2

- **位置**: `OcrResultForm.cs:331-395` 只按选中/悬停画三种框，未读 `PaddleOcrLine.RecognitionScore`。
- **价值**: 低置信度的形近字、模糊小字目前只能靠用户自己逐字核对；把置信度露出来可以
  快速定位「哪里可能识别错了」。
- **建议**:
  - 低置信度（阈值先用 0.7 左右，需用样本校准）画琥珀色虚线框，与选中/悬停样式区分；
  - 悬停状态栏显示「置信度 62%」，与现有行文本提示合并；
  - 先只做**展示**，不要默认过滤低分文本（过滤会静默丢内容，风险大于收益）；
  - 可选：工具栏加「只看低置信度」开关，方便校对。
- **改动面**: S/M（画框分支 + 状态文案）。

### O-9 高倍缩放后无法平移，只能看图片中心 — P2

- **位置**: `OcrResultForm.cs:265-284`；`:347-356` 的居中绘制。
- **现象**: 缩放上限 8×，但窗口超过工作区后 `FitWindowToImage` 直接 `return`，图片按窗口居中裁切；
  没有滚动条、没有平移偏移。放大看小字时只能看到中心，四周内容无法到达。
- **建议**: 增加 `_panOffset`（物理像素），绘制时加到 `ImageRect`；中键拖动或 Space+左键拖动平移，
  滚轮在未按 Ctrl 时纵向滚动；缩放时以鼠标位置为锚点，避免「一放大就跑到中心」。
  平移偏移按「图片边缘不进入窗口内侧」夹紧，避免拖出空白。
- **改动面**: M。

### O-10 状态栏长文本被硬裁 — P2（沿用 `ui-review` P2-4）

- **位置**: `OcrResultForm.cs:400-414`；`:413` 用 `Point` 重载 + `EndEllipsis`，没有边界矩形时不生效。
- **现象**: 识别失败的异常信息、很长的悬停行文本会超出窗口右边界被直接切掉。
- **建议**: 改用带 `Rectangle` 的 `TextRenderer.DrawText` 重载，宽度取
  `ClientSize.Width - bx - 8 - 2*padX`；悬停行文本超过一定长度先截断，再交给省略号。
  若担心丢失信息，可在右下角状态条上单击展开全文，或改用 tooltip。
- **改动面**: S。

但不要在界面上暗示「已取消」；需要的话，可在状态栏说明「上一次识别仍在后台完成」。

## 四、功能扩展建议

| 编号 | 扩展 | 价值 | 复杂度 | 建议优先级 |
| --- | --- | --- | --- | --- |
| F-1 | **单击文本块自动复制** | 用户明确要求；少按一次 Ctrl+C | S/M | 最高 |
| F-2 | 双击选词、三击选行、跨行拖选 | 选区体验接近文本编辑器 | M/L | 中 |
| F-3 | 启用 CTC 真实字符框（见 O-7） | 选词精度、逐字置信度 | M | 高 |
| F-4 | 低置信度可视化 + 低分时放大重试 | 让识别结果可审计 | S/M | 高 |
| F-5 | 多栏阅读顺序 / 竖排支持 | 文章、报刊类截图 | M/L | 中 |
| F-6 | 高倍缩放平移、滚轮滚动、隐藏识别框 | 查看小字/干净截图 | M | 中 |
| F-7 | 保存文本、复制原图、重新识别 | 补齐工作流 | S | 中 |
| F-8 | 右键菜单、快捷键提示 | 可发现性 | S | 低 |

**F-5 的边界**: 现有 `OcrTextChecks` 的用例 8 明确把「同高并列块」定义为 `L1, R1, L2, R2`
（行优先）。真正的两栏文章需要「左栏到底、再右栏」，与表格/UI 的行优先语义冲突。
因此不要无条件改 `SortReadingOrder`：要么加「多栏模式」开关，要么只在检测到稳定纵向空白且
两侧都有多行时启用。`ToCsv` 必须继续走行优先，不能跟着改。

**F-5 竖排**: 当前只处理 `AppliedRotationDegrees == 180`；竖排文字的检测框是窄高四边形，
`CharIndexAt` 仍沿顶边投影，选词会错。是否支持要先验证模型对竖排的识别率，成本较高，不建议近期做。

**F-4 放大重试**: 仅在「没有识别出任何行」或「平均置信度低于阈值且原图较小」时，
把图放大 2× 重新识别，再把返回框坐标除以 2 映射回原图。需要新增结果与缩放因子的包装类型；
不要让每次识别都无条件放大，否则 Tiny 档的速度优势会被吃掉。

## 五、F-1 单击自动复制（推荐方案）

### 目标

在结果窗口里**单击任意文本块**，立即复制该块文字，同时保留整行选中高亮；
不再需要先单击再按 `Ctrl+C`。

### 行为矩阵

| 操作 | 现状 | 建议 |
| --- | --- | --- |
| 单击文本块 | 选中整行 | 选中整行 + 复制该块，状态栏显示「已复制 N 字符」 |
| `Shift` + 单击 | 多选切换 | 保持不变，**不复制** |
| 块内拖动 | 字符级部分选中 | 保持不变，**松手不复制**（只有单击才复制） |
| 单击空白 | 清空选中，可拖动窗口 | 保持不变，**不复制**；顺带修 O-3 |
| 双击文本块 | 两次单击 | 会复制两次（内容相同，无副作用）；将来做双击选词时再抑制首次复制 |
| `Ctrl+A` / `Ctrl+C` | 全部选中/复制 | 保持；顺序按 O-4 修正 |
| 工具栏「复制选中」 | 复制当前选中 | 保持 |

### 复制范围

建议复制**当前命中的检测块**（`_lines[hit].Text`），与高亮框完全一致。
不要默认复制「同一视觉行合并后的整行」：表格截图里一个块就是一个单元格，合并会把相邻列粘进来。
若确实需要整行，再提供 `Alt+单击` 或右键菜单「复制整行」作为第二入口。

### 实现点

- `OnMouseUp`（`OcrResultForm.cs:655-685`）的单击分支里：
  1. 先把 `_dragLine` 存到局部变量（后面会置 -1）；
  2. `_charDrag && !_charDragMoved && clickedLine >= 0` 且设置允许时，选中该行后调用
     `CopyText(_lines[clickedLine].Text)`；
  3. **不要立即调用 `UpdateIdleStatus()`**，否则「已复制」会被「已选 N 字符」覆盖；
     由 `CopyText` 自己写状态即可。鼠标移到别的行时 `OnMouseMove` 会自然刷新状态。
- `CopyText`（`:832-849`）已处理空文本、剪贴板占用与失败提示，直接复用，不要另写一份复制逻辑。
- 只在 `Left` 单击、且未按 `Shift` 时触发；`_ocrDone == false` 时本来就没有可命中的块。
- 不要自动关闭窗口：用户经常需要连续复制多块。

### 开关

建议加设置 `AppSettings.ClickToCopy`（默认 `true`），托盘菜单加复选项「单击复制识别结果」。
理由：单击就改写剪贴板是副作用，用户在窗口里只是点着看时可能不希望覆盖原有剪贴板内容。
旧 `settings.json` 没有该字段时，依靠属性初始值得到 `true`；在 `SettingsCheck` 里断言
「旧 JSON 读入为 true」「显式 false 能保留」「默认新配置为 true」。
`OcrResultForm` 在点击时读取 `SettingsStore.Current.ClickToCopy`，打开中的窗口也能立即响应托盘切换。

### 状态与提示

- 空闲提示从 `单击/拖选 · Shift 多选 · Ctrl+滚轮缩放` 改为
  `单击复制 · 拖选文字 · Shift 多选 · Ctrl+滚轮缩放`。
- 复制成功：`已复制 12 字符`；失败：沿用 `复制失败 (剪贴板被占用?)`。
- 若块文本为空或全空白（`HitTest` 现在只判 `IsNullOrEmpty`），应显示「没有可复制的文本」，
  不要静默无反应。

### 测试

- **纯逻辑**: 如果抽出 `ShouldCopyOnMouseUp(charDrag, moved, shift, hit)`，离线覆盖矩阵；
  不抽也可以，直接在交互测试里覆盖。
- **InteractiveTests**: 构造 `OcrResultForm`，用反射注入 `_lines`、`_ocrDone=true`、
  `_lineCumW`，通过 `OnMouseDown`/`OnMouseUp` 在块中心模拟单击；
  断言 `Clipboard.ContainsText()` 且内容等于块文本；`Shift+单击` 后剪贴板不变；
  块内拖动后剪贴板不变；单击空白后剪贴板不变；`ClickToCopy=false` 时只选中不复制。
  测试结束恢复剪贴板原内容，避免污染用户环境。
- **DriveTest**: 真实 exe 里截一张含固定字符串的图，单击该块，再从剪贴板读回比对；
  同时检查状态栏截图里出现「已复制」。（注入类测试必须检查调用结果，沿用 AGENTS 的约定。）

### 验收标准

1. 单击任意非空文本块，剪贴板内容等于该块原文，高亮仍保持整行选中。
2. `Shift+单击` 只切换多选，不写剪贴板。
3. 块内拖选、单击空白、OCR 未完成时不写剪贴板。
4. 关闭开关后行为回到现状（只选中，Ctrl+C 才复制）。
5. 剪贴板被占用时状态栏有失败提示，不抛异常。

## 附: 已确认没有问题的点（避免返工）

- `OcrBox.Corners` / `TopEdge` / `BottomEdge` 的取点顺序一致，顶边与底边同向，
  `CharRangePoints` 不会自交。
- `AppliedRotationDegrees == 180` 在 `CharIndexAt` 与 `CharRangePoints` 两处都做了翻转，处理一致。
- 字符高亮与复制内容共用同一个 `_partial` 范围，二者不会出现「高亮一段、复制另一段」；
  O-1 是两者**同时**漏掉最后一个字符，修一处即可同时修好。
- `CopyText` 对空文本与剪贴板异常都有兜底，不会让窗口崩溃。
- `OcrService.Recognize` 先做瞬时 `LockBits` 快照，推理期间不持有位图锁，UI 可以继续重绘。
- 识别失败会进入 `_ocrDone=true` 分支，状态栏有提示，不会卡在「正在识别」。
