## P0 — 界面显示与实际不一致 (会让用户做出错误判断)

### P0-1 自定义热键后, 托盘菜单与提示仍写死 F1/F3 — **已修复**

- **位置**: `TrayController.cs:109-110` 菜单项文本 `"截图并识别 (F1)"` / `"截图并标注 (F3)"`;
  `:135` 托盘提示 `"SnipasteOCR - F1 截图识别 / F3 截图标注"`.
- **现象**: 热键可以在对话框里改, 改完弹窗告知成功, 但托盘菜单/悬停提示永远显示 F1/F3。
  用户会以为没生效, 或者按菜单里的键按不动。
- **建议**: 新增 `SyncHotKeyLabels(int mods, int ocrVk, int imageVk)`:
  用 `HotKeyManager.Describe` 生成 `截图识别 (Ctrl+Alt+Q)` 这类文本, `ModifyMenu(MF_BYCOMMAND)` 改两项,
  再用 `Shell_NotifyIcon(NIM_MODIFY)` 更新 `szTip`。启动时调一次, 改键成功后由 `Program` 再调一次。
  必须保留原 cmd id (`ModifyMenu` 不重建菜单), 否则 `ShowMenu` 里按位置还原 ID 的逻辑会错位。
- **改动面**: S (约 30 行 + 一处调用)。

### P0-2 两个热键共用一套修饰键, 第二个输入框显示的值可能是假的 — **已修复**

- **位置**: `HotKeyForm.cs:22` `Modifiers => _ocrBox.Modifiers` (只取第一个框);
  `HotKeyManager.RegisterAll(ocrVk, imageVk, modifiers)` 对两个动作用同一组修饰键。
- **现象**: 第一个框录 `Ctrl+Q`、第二个框录 `F3` → 实际注册的是 `Ctrl+F3`, 但第二个框显示 `F3`。
  用户按 F3 没反应、按 Ctrl+F3 才有反应, 而界面从未这样说过。
- **建议** (三选一):
  1. **各自存修饰键** (正确做法): `AppSettings` 增加 `HotKeyImageModifiers` (默认跟随 `HotKeyModifiers`),
     `RegisterAll(ocrMods, imageMods)`, 托盘菜单分别显示。需按项目约定做一次性迁移: 新增字段给默认值,
     老配置读入后 `HotKeyImageModifiers` 缺省取 `HotKeyModifiers`, 不能无条件改写用户已有选择。
  2. **共用修饰键 + 同步显示**: 任一框录制后把修饰键镜像到另一框 (保留各自键位), 提示改成
     "两个热键共用修饰键"。改动最小, 但录 F3 时另一框会突然变成 Ctrl+F3, 仍然反直觉。
  3. **对话框改成"一行修饰键 + 两个键位"**: 数据模型不变, 交互最清楚, 但要重排控件。
- **推荐**: 1 (与"两个热键可分别设置"的既有文案一致); 想省事就 2, 但不能保持现状。

## P1 — 直接可见的缺陷

### P1-1 工具栏翻到上方时压住尺寸徽标 (上一轮新增徽标带出的回归) — **已修复**

- **位置**: `SnipOverlayForm.cs:490-502` 上翻时 `y = sel.Top - tbH - margin` (tbH=42, margin=8);
  `SnipSizeBadge.cs:76` 徽标 `y = sel.Top - h - 6` (h≈26)。
- **现象**: 选区贴近屏幕底部时, 工具栏占到 `[sel.Top-50, sel.Top-8]`, 徽标占到 `[sel.Top-32, sel.Top-6]`,
  完全重叠。工具栏是子控件, 绘制在父窗口之上 → 徽标被整块盖住, 用户在"贴底框选"时看不到宽高。
- **建议**: 把"工具栏是否上翻"抽成唯一来源 (如 `SnipGeometry.ToolbarPlacement(sel, tbSize, client)` 返回位置 + 是否上翻),
  `PositionToolbar` 与徽标布局共用; 判定上翻时徽标直接放选区内侧 (与"顶部贴边"同一分支)。
  不要依赖 `_toolbar.Bounds` —— 拖拽过程中工具栏位置要到松手才更新, 会拿到旧值。
- **验证**: `SnipSizeCheck` 增断言"工具栏上翻场景下徽标与工具栏不相交且在客户区内"。

### P1-2 OCR 模式下「贴图」按钮可点但无反应 — **已修复**

- **位置**: `AnnotationToolbar.cs:323-324` 无条件绘制 pin 并参与命中;
  `SnipOverlayForm.cs:845-848` `PinToScreen` 在 `_mode != SnipMode.Image` 时直接 return。
- **现象**: F1 (识别) 流程里也能看到图钉按钮, 点下去毫无反应也不提示。
  AGENTS.md 写的是"贴图按钮只加在 F3 模式", 代码没有落实。
- **建议**: 工具栏加 `ShowPin` 属性, `ComputeLayout(width, showPin)` 在隐藏时不占位、不绘制、不命中;
  覆盖层按 mode 设置。`ToolbarCheck` 增断言: 隐藏时总宽度减少 `ButtonSize + Gap`, 原图钉位置不再触发事件。

### P1-3 双屏下提示条跨屏 / 结果窗口固定开在主屏 — **已修复**

- **位置**: `SnipOverlayForm.cs:216-217` 提示条按 `ClientSize` (整个虚拟屏) 居中;
  `OcrResultForm.cs:74` `StartPosition = CenterScreen` (永远是主屏)。
- **现象**: 本机双屏 3840×1080、接缝在 x=1920, 提示条约 470px 宽 → 横跨两块屏, 文字被接缝切开。
  在副屏框选后, 结果窗口却开在主屏, 用户视线要跳屏。
- **建议**: 以 `Screen.FromPoint(Cursor.Position)` 为基准: 提示条在该屏内居中 (y 用该屏底部);
  结果窗口改成 `Manual` + 在该屏工作区居中。同样地, `PositionToolbar` 的横向夹紧应限制在选区所在屏,
  否则选区贴着左屏右边缘时工具栏会整条跑到右屏上。
- **改动面**: M (三处坐标, 可共用一个小助手把屏幕矩形转成客户区矩形)。
- **修复 (2026-11-08)**:
  - 提示条按 `Screen.FromPoint(Cursor.Position)` 所在屏底部居中; 光标跨屏时只触发一次重绘
    (全屏底图重绘很贵, 不能每个鼠标移动都刷)。
  - `PositionToolbar` 经 `SnipGeometry.PickScreen` 取选区所在屏 (重叠面积最大), 再由
    `SnipGeometry.ToolbarLocation` 把上下翻转与水平回退都夹紧在该屏内。
  - `OcrResultForm` 改为 `Manual` 定位并接收覆盖层传入的选区屏幕矩形, 在该屏工作区居中;
    剪贴板识别无锚点时取光标所在屏。初始尺寸收缩也从 `SystemInformation.WorkingArea`(主屏)
    改成目标屏工作区, 否则副屏截图按主屏收缩。
  - 屏幕矩形换算到覆盖层客户区统一走 `ScreenRectToClient` (除以 `ScaleFactor`), 与选区/导出同一套坐标约定。
  - 验证: 离线 286 项全绿 (新增「多屏定位」12 项); 交互 68 项中 67 通过, 唯一失败为既有的
    「真实按键进入编辑控件」(输入法组合态, 非本轮回归)。本轮验证机只有一块 1920×1080 屏,
    真正的跨屏摆放由离线几何断言覆盖, 建议在双屏机器上人工确认一次。
  - AOT publish 通过 (win-x64 单文件, exit 0)。

### P1-4 热键对话框是固定像素布局 (待实机确认)

- **位置**: `HotKeyForm.cs:32-97` 全部 `Location/Size` 写死 (430×224, 每行 28px 高), 未设 `AutoScaleMode`,
  字号用 `UiFont.Create(12f)`。
- **风险**: 150%/200% 缩放下可能整体偏小或标签与输入框错位。本机 100% DPI, 无法下结论。
- **建议**: 先在 150% 实机看一眼; 若确实偏小, 用 `TableLayoutPanel` 重排 (比按 DPI 手算坐标稳),
  或补 `AutoScaleMode.Dpi` 后再实测一遍。

## P2 — 可用性与文案一致性

### P2-1 提示承诺支持 Win 组合键, 实际不生效 — **已修复**
`HotKeyForm.cs:38` 写"可组合 Ctrl / Alt / Shift / Win", 但 `:189-194` 只解析 Ctrl/Alt/Shift,
Win 组合既不会录入也不会提示。**建议**: 先把文案改成"Ctrl / Alt / Shift"(1 行);
再单独评估是否实现 Win (部分 Win 组合被系统保留, 需要 `RegisterHotKey` 失败提示兜底)。
**修复**: 文案已改为「Ctrl / Alt / Shift」, 不再承诺 Win 组合。

### P2-2 工具栏没有 tooltip — **已修复**
6 个工具图标 (尤其马赛克/画笔) 和撤销/重做/图钉/保存/确认/取消都没有文字提示, 快捷键 `1-6`/`0`/`Ctrl+Z`
也只写在 README 里。**建议**: 加一个 `ToolTip`, 在 `OnMouseMove` 按当前命中项
`SetToolTip("矩形 (1)")` / `"撤销 (Ctrl+Z)"` / `"贴图 (F3 模式)"`。悬停才出现, 不增加常驻视觉噪音。
**修复**: 工具栏共用 `ToolTip`, 悬停项变化时更新文本, 停留 450ms 后显式 `Show`
(同一控件内换按钮时只改文本不会重新触发悬停延迟, 显式 Show 才能切换; 计时也避免划过时连续闪提示);
覆盖 6 个工具、颜色、线宽、撤销/重做/贴图/保存/确认/取消; 移出可点区域立即隐藏。
交互自检断言提示文本与清空行为。

### P2-4 状态栏长文本被硬裁 — **已修复**
`OcrResultForm.cs:413` 用 `Point` 重载绘制, `EndEllipsis` 只在有边界矩形时生效;
识别失败时 "识别失败: " + 异常信息 很容易超出窗口右边界, 被直接切掉。
**建议**: 改用 `Rectangle` 重载, 宽度取 `ClientSize.Width - bx - 8 - 2*padX`; 顺便把 idle 提示缩短。

### P2-5 覆盖层提示缺两项信息 — **已修复**
`SnipOverlayForm.cs:213-215`: 右键实际会"先清空标注, 再退出", 但提示里只有 Esc;
F1 模式提示只写"确认", 没说明确认后是识别文字 (F3 已写"确认复制图片")。
**建议**: F1 → `拖拽选择区域 · 双击/回车 识别 · 右键/Esc 取消`; F3 → `… 复制图片 …`。
**修复**: 提示统一由 `HintText` 生成: 识别模式写「双击/回车 识别」, 图片模式写「双击 复制图片」,

### P2-6 结果窗口的移动方式不可发现 — **已修复**
无边框窗口, 只有按住空白处拖动才能移动 (OcrResultForm.cs:543-547), 界面上没有任何提示。
**建议**: 并入 idle 状态栏 (`拖动空白处移动窗口`), 或首次打开时显示 3 秒后自动回退, 不长期占用。
**修复**: 识别期间状态栏显示「正在识别… · 拖动空白处移动窗口」, 识别完成后回落到常驻操作提示,
不长期占用; 交互自检断言初始状态包含该提示。

## 建议的修复批次

1. **正确性 (P0 + P1-1/P1-2)**: 托盘热键文案、热键修饰键、徽标被遮挡、OCR 模式多余图钉。
   改完必跑 `AnnotationTests` + `InteractiveTests`, 涉及托盘/对话框的项需实机点一遍。
2. **多屏与文案 (P1-3 + P2)**: 提示条/结果窗口按光标所在屏定位、tooltip、术语与提示统一、状态栏省略号。
   多屏项本机可直接验证。
3. **打磨 (P3)**: 主题常量收敛、注释与拼写、标点。

第 1 批建议优先做 —— 两条 P0 都属于"界面在骗人", 第 3 条是上一轮徽标带出的遮挡回归。
